Status: ready-for-agent

## Problem Statement

## Solution

Deliver 100% rule catalog and active detector parity in `dotore` so that every single one of the 906 reference catalog rules (plus all project-level dead-code, cycle, duplicate-JSX, reduced-motion, React Native/Expo manifest, and supply-chain rules) is registered, resolves all canonical and legacy aliases, respects **Capability Gate** inference, and executes an active, deterministic Rust detector in the single-pass OXC pipeline:

1. **Wire all 53 registered metadata stubs to active Rust detectors**: Implement single-pass AST and semantic detectors for all 53 currently unwired rule variants across React class lifecycles, JSX conventions, **Subject** complexity/size checks, `design` layout heuristics, React Native style/animation rules, Ink terminal rules, TanStack Start loader checks, and JS/client performance rules.
2. **Register and implement all 163 unported catalog rules**:
   - Extend **Capability Gate** inference to detect React Router (`react-router`, `react-router-dom`, `@react-router/*`), Remotion (`remotion`, `@remotion/*`), Redux (`react-redux`, `@reduxjs/toolkit`), TanStack Form (`@tanstack/react-form`), TanStack Table (`@tanstack/react-table`), and TanStack Virtual (`@tanstack/react-virtual`).
   - Register all 155 net-new rules and wire the 8 canonical alias mappings so every one of the 906 reference rule IDs resolves to a typed `RuleId` with complete metadata (category, default severity, default enabled state, tags, **Capability Gate** predicate, **Contextual Owner** policy, **Prescription Tier**, and compiled-in remediation recipe).
   - Implement single-pass OXC AST and semantic detectors for React Router v7/v8, Motion, Remotion, TanStack Form/Table/Virtual, Redux, Radix/Base UI/shadcn/styled-components, **Effect Node** listener/observer/timer cleanup, and React/JS correctness rules.
3. **Deterministic `Autofix` and `Fix Capsule` integration**: Provide byte-range `Autofix` patches for mechanical transformations (such as `jsx-no-useless-fragment`, `jsx-fragments`, `js-tosorted-immutable`, `void-dom-elements-no-children`, `no-string-false-on-boolean-attribute`, `react-router-v8-no-react-router-dom-import`, and `rendering-svg-precision`) and **Fix Capsules** with **Root-Cause Grouping** and **Blast Radius** ranking for `Surgical` and `Refactor` rules.

## Implementation Decisions

1. **Zero Metadata-Only Stubs Invariant**:
   - Every `RuleId` variant in the rule registry must be backed by an active detector in the single-pass evaluation pipeline.
   - An automated registry-parity test will assert both that all 906 rule identifiers in the reference catalog resolve via `RuleId::parse` and that every `RuleId` variant in `dotore` is actively referenced by a rule detector module.
2. **Extended Capability Gate Inference**:
   - Extend the `Capability` enum and `CapabilityGate` dependency inference to recognize:
     - `ReactRouter` (`react-router`, `react-router-dom`, `@react-router/dev`, `@react-router/node`, `@react-router/serve`),
     - `Remotion` (`remotion`, `@remotion/cli`, `@remotion/player`, `@remotion/renderer`),
     - `Redux` (`react-redux`, `@reduxjs/toolkit`, `redux`),
     - `TanstackForm` (`@tanstack/react-form`),
     - `TanstackTable` (`@tanstack/react-table`),
     - `TanstackVirtual` (`@tanstack/react-virtual`).
   - Gate `react-router-*`, `remotion-*`, `redux-*`, `tanstack-form-*`, `tanstack-table-*`, and `tanstack-virtual-*` rules on their respective capabilities so unrelated projects incur zero noise.
3. **Canonical Alias Resolution for Naming Variants**:
   - Wire the 8 naming variants (`no-derived-useState` → `NoDerivedState`, `no-direct-state-mutation` → `NoDirectMutationState`, `no-effect-chain` → `NoChainStateUpdates`, `no-effect-event-handler` → `NoEventHandler`, `no-event-trigger-state` → `NoEventHandler`, `no-mirror-prop-effect` → `NoAdjustStateOnPropChange`, `prefer-useReducer` → `PreferUseReducer`, `query-no-usequery-for-mutation` → `QueryNoUseQueryForMutation`, `rn-style-prefer-boxshadow` → `RnStylePreferBoxShadow`) directly into `RuleId::parse` and `RULE_REGISTRY` `legacy_aliases` so both canonical and legacy keys resolve identically.
4. **Domain-Grouped Single-Pass Detector Submodules**:
   - Organize the new and newly wired detectors into cohesive domain submodules under the rules engine (such as `react_router`, `remotion`, `state_and_effects`, `react_builtins`, `correctness`, `architecture`, `js_performance`, `performance`, `design`, `a11y`, `tanstack`, `react_native`, `stores`, and `ecosystem_ui`) invoked during the single `oxc_parser` + `oxc_semantic` extraction pass.
   - Preserve single-pass performance: no rule may re-invoke `oxc_parser` or spawn external processes; all checks operate on the shared `oxc_semantic::Semantic` graph, `FileIr`, and `ProjectGraph`.
5. **Deterministic `Autofix` and `Fix Capsule` Support**:
   - Provide `ByteEdit` `Autofix` patches for unambiguous single-node rewrites (`jsx-no-useless-fragment`, `jsx-fragments`, `js-tosorted-immutable`, `void-dom-elements-no-children`, `no-string-false-on-boolean-attribute`, `react-router-v8-no-react-router-dom-import`, `rendering-svg-precision`, `no-Deprecated-keyboard-event-keycode-which`).
   - Provide compiled-in remediation recipes, **Contextual Owner** policies, and **Fix Capsule** support for all newly registered rules.

## Testing Decisions

1. **Single High-Level Testing Seam (Crate-Root Library Interface)**:
   - All 216 rules (53 wired stubs + 163 newly ported rules), **Capability Gate** inference, alias resolution, and `Autofix` round-trips will be tested exclusively through the existing top-level crate-root entrypoints (`analyze_source_with_config`, `analyze_project_sources`, `apply_patches_to_source`, and `build_rule_catalog`).
   - Testing at this single seam exercises the complete `oxc_parser` → `oxc_semantic` → `FileIr` → `ProjectGraph` → `CapabilityGate` → rules engine → `Autofix` pipeline in memory without coupling tests to internal submodule structures.
2. **What Makes a Good Test**:
   - Every rule family test suite must test observable external behavior:
     - **Invalid cases**: asserting that violating code emits the exact `RuleId`, 1-based line/column, and `PrescriptionTier`.
     - **Adversarial valid cases**: asserting that valid look-alike code (guarded expressions, proper cleanup functions, memoized inputs, non-matching **Capability Gates**) emits zero diagnostics.
     - **Round-trip `Autofix` cases**: asserting that `apply_patches_to_source` produces valid syntax that re-analyzes with zero remaining diagnostics.
     - **Catalog parity invariant test**: asserting that 100% of the 906 rule identifiers in the reference catalog resolve through `RuleId::parse` and that 100% of `RuleId` variants have active detector coverage.
3. **Modules Under Test & Prior Art**:
   - Modules exercised through the crate-root seam include the configuration and **Capability Gate** loader, the single-pass OXC IR extractor, `ProjectGraph`, the rules registry and domain detector submodules, and the byte-range auto-fixer.
   - Prior art: existing table-driven integration test suites (`tests/ticket_07_rules_and_cold_path_graph.rs`, `tests/performance_and_bundle_rules.rs`, `tests/a11y_design_and_reduced_motion.rs`, `tests/ecosystem_rules.rs`, `tests/three_r3f_webgl_rules.rs`, and `tests/autofix.rs`).
