Features

Cross-file analysis, only the rules you need.

Parse each file once, build a cross-file project graph, and activate only the rules that match your project.

⌘

Cross-file root causes

Connect caller sites, render cascades, circular dependencies, and architecture boundaries instead of reviewing isolated warnings.

±

Deterministic autofixes

Apply syntax-verified AST byte-range patches with dotore fix, or preview every change with --dry-run.

◎

Automatic capability gates

Manifests determine active rules. React checks stay out of Angular projects, and libraries skip application-only checks.

P0

Prioritized remediation

Group findings by root cause and blast radius, then generate Fix Capsules ranked from P0 to P3.

Δ

Diff-aware adoption

Scan changed files, contextual owners, or changed lines. Baselines let legacy repositories block only new regressions.

→

Coding-agent handoff

Send structured findings, source excerpts, invariants, and suggested patches to your coding agent.

Questions

Using dotore with your existing tools.

Why use dotore alongside ESLint, Ruff, and Clippy?

dotore analyzes multiple ecosystems in one Rust binary and adds cross-file caller sites, render cascades, root-cause grouping, Fix Capsules, and a shared Health Score. Rules activate automatically from your manifests.

Can I adopt it incrementally in a legacy monorepo?

Yes. Use dotore check --scope contextual --base origin/main or dotore check --baseline baseline.json so CI focuses on changed code or newly introduced regressions.

How does coding-agent handoff work?

Run dotore check --handoff. dotore creates a structured remediation bundle with subject and caller-site excerpts, invariants, and exemplars, then launches a supported coding agent or prints the bundle.

Does dotore require configuration?

No. It works out of the box and infers capabilities from package.json, angular.json, pyproject.toml, and Cargo.toml. Optional configuration can override rules, ignored files, and tags.
